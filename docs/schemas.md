# Canonical Schemas

These schemas are intentionally lightweight. They define the shared language for future modules without forcing a database or heavy framework.

TypeScript interface contracts for future provider work live in `src/dataContracts.ts`. Runtime fixture validation lives in `src/localDataContracts.js`, with examples in `data/local-data-fixtures.json`. See `docs/local-data-contracts.md` for the local-first integration contract.

## Holding

Represents one position in one account.

Local brokerage CSV/JSON imports preview normalized `Holding` rows before they are applied. Same ticker in different accounts remains separate. Same ticker/account rows from lot-level exports are merged with a visible duplicate-merge report.

- `id`: stable local id, usually `account:ticker`
- `accountId`: optional link to an account contract id
- `ticker`: normalized uppercase ticker, e.g. `MU`
- `name`: company, ETF, fund, or cash name
- `account`: display account name
- `accountType`: `Taxable`, `Retirement`, `HSA`, or `Unknown`
- `shares`: numeric share/unit count
- `price`: latest known price
- `marketValue`: current position value
- `costBasis`: total cost basis
- `unrealizedGain`: dollar gain/loss when available
- `unrealizedGainPercent`: decimal gain/loss, e.g. `0.25`
- `dailyChange`: dollar daily change
- `dailyChangePercent`: decimal daily change
- `targetWeight`: target portfolio weight as decimal
- `sector`: sector/theme label
- `assetClass`: `Equity`, `ETF`, `Cash`, `Treasuries`, `Option`, `Crypto`, or provider value
- `strategySleeve`: portfolio sleeve such as `Core index` or `AI / semiconductor`
- `thesisStatus`: current local thesis state
- `riskLevel`: display risk level
- `quant`, `valuationGrade`, `growthGrade`, `profitabilityGrade`, `momentumGrade`, `revisionsGrade`: Seeking Alpha-style fields
- `dividendYield`: decimal yield
- `nextEarnings`: date string
- `source`: primary source label
- `sourceAsOf`: source timestamp/date

Implemented in `src/portfolioSchema.js`.

## DataSource

Represents where a row or event came from.

### Canonical Data Mode Labels

User-facing screens should use this small vocabulary for source/data state:

- `Sample`: local example data used to demonstrate workflow; never Tucker's real portfolio and never live provider output.
- `Imported`: local CSV/JSON/XLSX/manual data that Tucker loaded or entered.
- `Live`: data fetched through the local backend from a configured provider.
- `Cached`: previously fetched provider data still inside its freshness window.
- `Stale`: cached/provider data past its freshness window or used after a refresh failure.
- `Error`: provider/import refresh failed or returned an unusable response.
- `Not configured`: no approved provider credentials or connector path is active.

Internal raw values such as `mock`, `demo`, `mock/sample mode`, `connected`, `configured-not-connected`, and `stale data` may still exist for backward compatibility. UI labels should map those raw values into the canonical labels above.

- `id`: local source id
- `type`: `csv`, `xlsx`, `provider`, `demo`, `manual`, `api`, `social`, `filing`, or `market-data`
- `provider`: Fidelity, Plaid, SnapTrade, Seeking Alpha, etc.
- `sourceAsOf`: source timestamp/date
- `importedAt`: local import timestamp
- `status`: `demo`, `imported`, `configured`, `setup-required`, `missing-key`, `error`, `disabled`, or `stale`
- `warnings`: non-blocking issues

## MarketDataQuote

Represents provider-normalized quote and price context before it touches holdings, risk analytics, or ticker signal scoring.

- `id`: stable quote id, usually `quote:TICKER`
- `ticker`: normalized uppercase ticker
- `name`: security/company/fund name
- `price`: current/latest quoted price from the provider
- `previousClose`: previous close used to calculate daily move
- `dailyChange`: dollar change per share/unit
- `dailyChangePercent`: decimal daily change, e.g. `0.014`
- `marketCap`: optional company/fund market cap when available
- `volume`: latest volume
- `averageVolume`: optional average volume
- `sector`: provider sector/theme
- `industry`: provider industry/subsector
- `fiftyTwoWeekHigh` / `fiftyTwoWeekLow`: optional range markers
- `historicalPrices`: basic close series for future charts or momentum work
- `providerId` / `providerLabel`: source identity
- `sourceMode`: `mock`, `demo`, `live`, or `not-configured`
- `dataFreshness` / `cacheStatus`: `live`, `cached`, `stale`, or `mock`
- `fetchedAt`: local backend refresh/cache timestamp
- `providerName`: provider display name
- `lastSuccessfulRefresh`: most recent successful backend refresh
- `lastError`: last provider/cache refresh error when applicable
- `isMock`: true for local fixtures
- `liveProviderCalls`: true only for an approved server-side provider path
- `asOf` / `staleAfter`: provider timestamp and freshness guardrail

`src/marketDataProvider.js` is sample-first and now supports Finnhub and Financial Modeling Prep through the local backend proxy. Sample quotes must be labeled `Sample`; live/cached/stale quotes must expose freshness metadata.

## MarketDataProviderConfig

Represents server-side readiness for quote/profile/history providers.

- `selectedProvider`: provider id from `MARKET_DATA_PROVIDER`; defaults to `finnhub`
- `selectedLabel`: display name
- `recommendedProvider` / `recommendedLabel`: current first-choice provider path
- `configured`: true only when the selected provider key is present in local `.env`
- `liveEnabled`: true only for implemented server-side provider paths
- `liveProviderCalls`: true only when a server-side key is configured for an implemented provider
- `cacheTtls`: quote/profile/history cache TTL configuration
- `status`: `not configured`, `configured-not-connected`, `live-ready`, `disabled`, `connected`, `cached`, `partial data`, `rate limited`, `error`, or `stale data`
- `missingEnv`: required server-only env names
- `capabilities`: fields the future adapter is expected to provide
- `exposesSecretValues`: must remain false

Finnhub is the recommended first provider path because its official quote/profile/candle endpoints cover current price, daily move, open/high/low, previous close, market cap, candle volume when available, industry context, and historical candles through the server-side proxy. Financial Modeling Prep remains a supported fallback; Alpha Vantage, Polygon, and Twelve Data stay represented as future alternatives.

## NewsUpdate / ExternalSignal

Represents a normalized external context row for the news engine. It is a local-first envelope around X/Twitter notes, Reddit mentions, and federal trade disclosures. Provider-specific records can still keep their native models, but cross-source news views should consume this normalized shape.

- `id`
- `modelVersion`
- `kind`: `news-update`
- `sourceType`: `x`, `reddit`, or `federal-trade`
- `sourceMode`: `mock`, `manual`, `local-file`, `api`, `public-static-dataset`, `not-configured`, or `blocked`
- `sourceLabel`
- `providerId`
- `providerLabel`
- `liveProviderCalls`
- `signalType`
- `signalSubtype`
- `actionability`: `review-context-only`
- `trustLevel`
- `primaryTicker`
- `tickers`
- `headline`
- `summary`
- `sentiment`
- `sourceIds`
- `sourceUrl`
- `occurredAt`
- `detectedAt`
- `staleAfter`
- `warnings`
- `metadata`

Rules:

- X/Twitter rows are manual/local by default. Config-gated server-side X API rows may use `sourceMode: api`, but scraping, browser-cookie capture, paid feed shortcuts, and session-based collection must normalize as `sourceMode: blocked` instead of pretending to be compliant data.
- Reddit rows can come from local JSON or a compliant backend Reddit API path. They remain lower-trust social signals and must not store usernames.
- Federal trade rows can come from local files or a config-gated public dataset. They are delayed disclosure context only and must not imply motive, causation, or a buy/sell command.
- Every row must carry a human-readable `sourceLabel` and explicit `liveProviderCalls` so sample, imported, public, blocked, and live-like contexts cannot blur together.

- Missing live/cached market data, news/events, X/Reddit rows, macro data, or estimate revisions must be shown as missing data instead of invented narrative.
- The report may suggest screens to inspect next, but must not issue buy/sell commands, price targets, or guaranteed predictions.
